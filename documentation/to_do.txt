1.3 AI Pipeline Scripts (/ai)
- ai/ingest.py — CLI entry: python ingest.py <pdf_path> [--company NAME] [--year YEAR]
- ai/pdf_parser.py — Section-aware extraction using pdfplumber:
- Extract text by section: "Risk Factors", "MD&A", "Financial Statements", "Business"
- Handle SEC 10-K and India DRHP/Annual Report structures
- Return: {sections: [{title, text, page_start, page_end}], metadata: {company, year, source}}
- ai/chunker.py — 512-token overlapping windows (50-token overlap):
- Use tiktoken (cl100k_base) for token counting
- Preserve section metadata in each chunk
- Output: [{text, tokens, section, page, chunk_id}]
- ai/embedder.py — sentence-transformers/all-MiniLM-L6-v2:
- Batch encode chunks (batch_size=32)
- Return numpy array (n_chunks, 384)
- ai/faiss_manager.py — FAISS IndexFlatIP (cosine similarity):
- create_index(embeddings) → faiss.Index
- save_index(index, path) / load_index(path)
- search(index, query_embedding, k=5) → distances, indices

CREATE TABLE companies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  ticker TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL,
  market TEXT CHECK (market IN ('SEC', 'NSE', 'BSE')),

-- documents
CREATE TABLE documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID REFERENCES companies(id),
  year INT NOT NULL,
  source_url TEXT,
  file_path TEXT,           -- Supabase Storage path
  faiss_index_path TEXT,    -- Supabase Storage path
  chunk_count INT,
  status TEXT DEFAULT 'processing',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- chunks
CREATE TABLE chunks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id UUID REFERENCES documents(id),
  chunk_index INT NOT NULL,
  text TEXT NOT NULL,
  section TEXT,
  page_start INT,
  page_end INT,
  token_count INT,
  embedding_id INT,         -- FAISS internal index
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- risk_snapshots (for comparison results)
CREATE TABLE risk_snapshots (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  doc_b_id UUID REFERENCES documents(id),
  new_risks JSONB,
  removed_risks JSONB,
  amplified_risks JSONB,
  llm_summary TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

2.1 Compare Engine (ai/compare.py)
- load_document_index(doc_id) — download FAISS index + chunks from Supabase
- compute_pairwise_similarity(index_a, index_b, chunks_a, chunks_b):
- For each chunk in A: search top-1 in B → cosine similarity
- For each chunk in B: search top-1 in A → cosine similarity
- Return similarity matrix (n_chunks_a, n_chunks_b) or paired results
- Risk classification logic:
- NEW: chunk in B with max_sim < 0.4 to any chunk in A
- REMOVED: chunk in A with max_sim < 0.4 to any chunk in B
- AMPLIFIED: max_sim 0.4–0.7 AND severity keywords present in B but not A
- UNCHANGED: max_sim > 0.7 (optional, for completeness)
- Severity keyword dictionary:
SEVERITY_KEYWORDS = {
    'critical', 'material', 'significant', 'adverse', 'unprecedented',
    'severe', 'regulatory', 'lawsuit', 'breach', 'investigation',
    'penalty', 'fine', 'sanction', 'default', 'bankruptcy',
    'liquidity', 'solvency', 'going concern', 'impairment'
}
- Output structured JSON:
{
  "new_risks": [{"text": "...", "section": "Risk Factors", "page": 12, "similarity": 0.23}],
  "removed_risks": [{"text": "...", "section": "MD&A", "page": 8, "similarity": 0.31}],
  "amplified_risks": [{"text_a": "...", "text_b": "...", "severity_keywords": ["material", "lawsuit"]}],
  "metadata": {"doc_a": "AAPL-2022", "doc_b": "AAPL-2023", "total_chunks_a": 450, "total_chunks_b": 480}
}
2.2 RAG Chain for LLM Explanation (ai/rag_chain.py)
- LangChain RetrievalQA setup:
- Retriever: custom FAISS retriever wrapping faiss_manager.search()
- LLM: ChatOpenAI(model="gpt-3.5-turbo", temperature=0, streaming=True)
- Fallback: Ollama (llama3:8b) via ChatOllama if OpenAI fails
- Prompt template:
PROMPT_TEMPLATE = """You are a senior financial risk analyst. Given these disclosure excerpts from {company} annual reports ({year_a} vs {year_b}), explain the key risk changes in 3 concise bullet points. Focus on: what new risks appeared, what risks were removed, and what risks intensified. Cite specific language changes.

Context from {year_a}:
{context_a}

Context from {year_b}:
{context_b}

Changes detected:
- New risks: {new_count}
- Removed risks: {removed_count}
- Amplified risks: {amplified_count}

Analysis:"""
- Retrieval: fetch top-5 changed chunks (new + removed + amplified) as context
- Streaming: yield tokens via SSE for real-time UI effect
